# Sigma 코드 서식 규약 — 검사·적용 스킬

이 스킬은 두 가지를 제공한다.

1. **규약을 깊이 이해하기 위한 자료의 위치** — 정본 명세와, 규약대로 쓰인 워크드 예제(`app/`).
2. **기계검사 절차** — 빌드된 `sak` 프로그램으로 일부 규칙을 싸고 빠르게 1차 검출하는 방법.

경로는 모두 **이 프로젝트 루트 기준**이다(이 스킬은 `.claude/skills/sigma-style/`에 있으므로 루트는 세 단계 위).

## 1. 규약을 이해하는 법

### 1.1 정본 명세

- `Sigma_Coding_Convention.md` — **단일 정본.** 모든 판단의 근거는 이 문서다. 검사·수정 전에 통독한다.
  - §1 기본(행 폭·탭 들여쓰기), §2 제외 대상, §3 문법 강제, §4 토큰 4분류, §5 괄호(단일행/다중행·가상 괄호·숨은 중괄호), §6 개행 우선순위, §7 개행 상태, §8 공백, §9 개행 원칙, §10 스타일(네이밍).

### 1.2 워크드 예제 — `app/`

`app/`의 소스는 **그 자체가 규약을 따라 쓰인 모범 예제**다. 규칙을 추상적으로만 읽지 말고, 이 코드에서 규칙이 실제로 어떻게 적용됐는지 대조하며 익힌다.

- `app/lexer.cpp`, `app/lexer.hpp` — **§2 제외 대상의 기준 구현.** 주석(`//`, `/* */` 다중행), 문자열(`"…"` 이스케이프), 문자(`'…'` 숫자 구분자 `1'000` 휴리스틱 포함), 원시 문자열(`R"d(…)d"` 다중행·접두사 `R/LR/uR/UR/u8R`), 전처리기 행(`#…` 통째·`\` 줄연장)을 좌→우 모드 추적으로 가려낸다. "무엇이 코드이고 무엇이 제외 영역인가"의 판단 기준으로 삼는다.
- `app/check.cpp` — **기계검사가 실제로 하는 일.** 어떤 규칙을, 원문 행 위에서 보는지 마스크 위에서 보는지, 위반을 어떤 좌표로 내는지 보여준다.
- `app/main.cpp` — CLI(대상 확장자·재귀·종료코드)와 출력 형식.

## 2. 기계검사(sak)가 커버하는 범위 — 가장 중요

`sak`은 규약 전체가 아니라 **렉서 수준에서 위양성 0으로 확실히 잡히는 규칙만** 검사한다. 단계 1·2·3·3.5·4·6·7·8·9 의 확장으로 이제 **§3 일부·§5 일부·§8 일부·§9 일부**까지 포괄한다. 1차로 sak을 돌려 이것들을 싸게 걸러낸 뒤, **나머지(와 아래 '커버리지 안쪽의 제외분')는 반드시 직접 검사**해야 한다.

> **`sak edit` 로 먼저 자동 교정.** `sak edit <file|dir>` 은 공백·탭만으로 결정적으로 고칠 수 있는 위반 — §8.3~§8.5 간격, §5.4~§5.6 구조적 들여쓰기 — 을 파일에 직접 적용하고(개행·비공백 불가침, 회귀 게이트로 증명), 개행 이동·비공백이 필요한 나머지는 `[manual]` 로 남긴다. 서브에이전트는 먼저 `edit` 을 걸어 간격·들여쓰기를 넘긴 뒤 `[manual]` 잔여에 집중하면 토큰·시간이 준다. 자세히는 `sak_coverage.md` 2.5절.

### sak 커버리지 **안쪽의 제외분** (그 규칙이라도 아래는 사람이)

sak 가 위 규칙을 보긴 하나, *위양성 0* 원칙상 아래는 일부러 건너뛴다 — **여기는 여전히 사람 몫**이다.

- **§3 제어문 중괄호** — 조건 `(…)` 가 **인접 행(약 4행) 안에 닫히는 경우만**. **3행 이상 걸친 조건**과 **매크로가 본문을 제공하는 경우**는 제외 → 직접 본다. (do-while 꼬리는 정확.)
- **§3 키워드 위치** — **기본 타입 키워드 인접분만** 자동 확정(`const int`·`int static`). **사용자 정의 타입 인접**(`Foo const`/`const Foo`)·다중행 선언은 직접 본다. (`if constexpr` 는 단어쌍이 아니라 자연 제외.)
- **§3 단항 병기** — `- -`/`+ +` 중 **첫 부호가 단항으로 확실한 자리만**(직전이 여는괄호·구분자·양쪽공백 이항연산자). 직전이 피연산자라 단·이항이 갈리는 자리는 직접 본다. (`! !`·`~ ~` 는 붙여도 의미 동일이라 비대상.)
- **§5.4 다중행 괄호** — `< >` 자리 중 **두 앵커 밖만** 직접. `template<>` · `*_cast<>`(단계 8)에 더해 **닫힘 신호 앵커**(단계 9 — `>` 뒤 첫 토큰이 표현식을 못 여는 자리: `{;,)]}?`·`/%|^=`·`:`⧵`::`·`&&`·복합대입·`->`·`const`류)도 이제 sak. **직접 볼 것은 `Foo<T> x`(변수선언·word 뒤따름)·`>(`·`> ::` 처럼 비교와 여전히 모호한 나체 `<>` 뿐.**
- **§5.5 가상괄호** — 변수선언 자리 (★ 서브에이전트 스윕 표적, 단 마커 있으면 반자동):
  - **변수선언 `[타입명]『…』;`** — `int x;` 와 `int f();` 가 어휘적으로 동일(vexing parse) 라 앵커 없이는 sak 가 가를 수 없다. **끝판왕 · top-1 반복 미스, 유일한 top-notorious.** 특히 `auto (const) 이름 = [람다];` 관용구가 흔함.
  - **§11.2 2칸 마커가 있으면 이제 sak 이 반자동으로 잡는다** — 타입 끝·개행 직전 잉여 2칸을 후보로 보고 닫는 `;`(중첩 skip) 으로 재검증. **새로 쓰거나 고치는 다중행 변수 선언엔 이 마커를 남겨** 이 자리를 sak 으로 끌어오라. 마커 없는 기존 선언은 여전히 수동 스윕.

  > `:` 가상괄호(상속·enum base·ctor init)는 2026-07-01 단계 7 에서 sak 이 편입 — 렉서 수준에서 위양성 0 으로 분리 가능 (키워드 앵커·`?` 스택). 서브에이전트 관심에서 빠짐.
- **§8.3 문맥 의존 기호형 토큰** — sak 가 일부러 건드리지 않는 토큰들. 분류가 문맥에 좌우되어 위양성 0 보장 불가.
  - `*` `&` `&&` (역참조/곱셈/주소/데코레이터/참조한정사/우값참조)
  - `+` `-` (단항 부호/이항 산술)
  - `<` `>` (비교/꺾쇠/스페이스십 부분)
  - `:` (§4 표 7 역할)
  - `<<` `>>` (시프트/스트림/템플릿 닫힘 모호)
  - `::` (범위해결 vs 전역)
  - `!` `~` (좌측 공백 룰이 문맥적)
  - `...` (가변인자 / fold)
  - **`operator` 키워드 뒤 첫 기호형은 함수명의 일부라 §8.3 자동 제외**.
- **§8.4** — 꺾쇠 `< >` 경계 자리 중 **두 앵커(단계 8 `template<>`·`*_cast<>`, 단계 9 닫힘 신호) 밖만** 직접. `template<class T>` · `static_cast<T>(p)` · `Vec<int> const&` · `sizeof(Vec<int>)` 는 이제 sak.
- **§8.5** — 단일행 `< >` 꺾쇠 중 **두 앵커(단계 8·9) 안쪽 공백은 이제 sak** (중첩 단계 기반 n). 그 밖 앵커 없는 `<>`·`[[ ]]`·다중행 괄호는 §5.4 가 맡거나 서브에이전트 몫.
  - **꺾쇠 안 괄호-중첩 꺾쇠 `< (…<…>…) >` — sak 은 용의자 지목까지, 최종 공백은 서브에이전트.** sak 은 `(...)` 를 통째로 skip 하므로 **괄호 속 중첩 꺾쇠를 바깥 꺾쇠의 §8.5 중첩 단계에 세지 못한다**(과소평가 — 예: `Decay_t< decltype(Mock<X>()) >` 를 깊이 0 으로 봐 "안쪽 공백 0" 을 요구할 수 있음). 이 자리에서 sak 의 §8.5 검출은 **정밀히 좁혀진 용의자 지목**으로만 받고 sak 이 준 n 을 그대로 믿지 말 것 — 서브에이전트가 바깥 `<…>` 텍스트 범위 안의 **괄호 속 중첩 꺾쇠 깊이까지 직접 세어**(`(...)` 경계는 세기의 벽이 아니라 sak 의 스캔 한계일 뿐) 올바른 n 을 넣는다.
- **§9.3** — `)` + 단어 형태 한 가지만 잡는다. **단어+단어·단어+여는괄호·`}`+단어·공행 분리 자리** 는 §5.5 가상괄호 발현 (다중행 변수선언/using/`:`상속 등) 과 충돌해 sak 무위양성 영역 밖.
- **§9.4** — 다중행 이항연산자 인접 공행 (예: `result\n= compute_a()\n+ compute_b();` 자리 위·아래) 은 sak 아직 안 잡음 (§8.3 다중행 토큰 인식 필요). 인접 행이 **전처리 본문 (`\` 연장 행 포함)** 이거나 **주석/문자열 only** 면 들여쓰기 비교에서 제외된다 (§2 제외 대상). 다중행 괄호 인접 공행은 sak 이 커버.

### sak 가 **검출하나 면제 판정이 필요한** 패턴 — 서브에이전트 몫

#### statement-like 매크로 호출 (`BEGIN_CODE_BLOCK(…)` / `END_CODE_BLOCK(…)` 류)

세미콜론 없이 끝나는 매크로 호출이 블록 가드 역할을 하는 패턴 (gtest `TEST(…){…}`, gmock `MOCK_METHOD(…)`, Boost `BOOST_AUTO_TEST_CASE(…)`, Qt 매크로 등 포함). sak 가 §5.4·§9.3·§9.4 위반으로 잡지만 사용자 의도 idiom 일 수 있다.

**서브에이전트 면제 휴리스틱** (다음 모두 만족 시 statement-like 매크로 호출로 가정해 §5.4·§9.3·§9.4 검출을 면제):

1. 식별자가 **ALL_CAPS** (대문자·언더바·숫자만)
2. 식별자 직후 같은 행에 `(...)` 단일행
3. 그 행에 *같은 행 안의 `;` 가 없음* (호출 단독으로 행이 끝)

만족 안 하는 자리 (`ASSERT_EQ(a, b);` 처럼 세미콜론 동반·소문자 함수 호출 등)는 정상 검출을 그대로 신뢰한다.

### sak 이 **못** 잡는 규칙 (반드시 사람이 직접 검사)

**★ 서브에이전트 매 파일 표적 스윕 (top-notorious):**
- **§5.5 변수선언 가상괄호** (vexing parse). 끝판왕 · 유일한 top-notorious 자리. **단 §11.2 2칸 마커가 있으면 sak 이 반자동으로 잡으니, 새 코드엔 마커를 남겨 이 부담을 줄인다.**

그 외 사람 몫:
- **§3 나머지** — 키워드 위치·단항 병기의 잔여분 (사용자 정의 타입 인접·다중행 선언·단이항 모호분).
- **§8.3 문맥 의존 토큰** — `*` `&` `&&` `+` `-` `<` `>` `:` `<<` `>>` `::` `!` `~` `...`.
- **§9.4 다중행 이항연산자 인접 공행** — sak 이 커버 못하는 자리.
- **§2 한계** — `#if 0` 비활성 분기는 sak 이 추적 안 함.
- **전각=2 가정** — sak 의 §1.1 폭 계산은 CJK 를 폭 2로 본다. 경계값은 사람이 재확인.

### Don't Care — 검출·수정 대상 외

sak 도 서브에이전트도 검사·교정하지 않는다. 정본에는 있으나 파이프라인에서 배제 (2026-07-01 신설).

- **§3 void 외 후행 반환 타입 강제** — vexing parse + 스타일 편차 + 자동 수정 위험.
- **§10.1 네이밍** — 리네임 파급이 커서 자동 판단 위험.
- **§11.1 라행선** — 규약이 "권장 — 부재는 위반 아님" 명문화.
- **§11.2 변수선언 2칸 마커** — 규약이 "권장 — 부재는 위반 아님" 명문화. 다만 마커가 **있으면** sak 이 §5.5 변수선언 감지 힌트로 활용한다.

**§4·§5.3·§6·§7·§9.1·§9.2** 는 검사 항목이 아니라 §8·§9 가 딛는 **정의·원리** 다. 서브에이전트의 관심 목록에 넣지 않는다.

## 3. 기계검사 실행 절차

### 3.1 헬퍼 스크립트 (권장)

```sh
.claude/skills/sigma-style/check.sh <file|dir>          # 검사만
.claude/skills/sigma-style/check.sh --edit <file|dir>   # 공백·탭 자동 교정 후 잔여 보고
```

- `build/sak`이 없으면 자동으로 cmake 구성·빌드 후 실행한다(이후엔 기존 `build/` 재사용).
- 디렉터리를 주면 하위까지 재귀(`-r`) 검사한다.
- `--edit` 는 `sak edit` 로 전달 — 간격·구조적 들여쓰기를 자동 교정하고 `[manual]` 잔여를 남긴다.
- **종료코드:** `0` 위반/잔여 없음 / `1` 위반·잔여 있음 / `2` 사용법·경로 오류. 1로 끝나는 건 정상 동작이며 스크립트 실패가 아니다.

### 3.2 직접 실행

```sh
cmake -S . -B build && cmake --build build   # 최초 1회 (또는 ./setup.sh)
./build/sak <file>              # 파일 하나 검사
./build/sak -r <dir>            # 디렉터리 재귀 검사
./build/sak edit <file|dir>     # 공백·탭 자동 교정 (-n/--dry-run 으로 미리보기)
```

### 3.3 출력 파싱

```
<경로>:<행>:<열> [<규칙>] <메시지>
[sak] <N> file(s), <M> violation(s)      # 디렉터리 검사 시 요약 행
```

- 행·열은 1-기준. `<규칙>` 은 `1.1` `1.2` `3` `5.4` `5.5` `5.6` `5.7` `8.1` `8.3` `8.4` `8.5` `9.3` `9.4` 중 하나. (`edit` 모드는 각 줄 끝에 `(fixed)` 또는 `[manual]` 를 덧붙인다.)
- 빌드가 불가능한 환경(컴파일러/cmake 부재)이면 1차 기계검사를 건너뛰고 sak 커버 규칙까지 포함해 **전부 수동 검사**로 전환한다.
