# Sigma 코드 서식 규약 — 검사·적용 스킬

이 스킬은 두 가지를 제공한다.

1. **규약을 깊이 이해하기 위한 자료의 위치** — 정본 명세와, 규약대로 쓰인 워크드 예제(`app/`).
2. **기계검사 절차** — 빌드된 `sak` 프로그램으로 일부 규칙을 싸고 빠르게 1차 검출하는 방법.

경로는 모두 **이 프로젝트 루트 기준**이다(이 스킬은 `.claude/skills/sigma-style/`에 있으므로 루트는 세 단계 위).

## 1. 규약을 이해하는 법

### 1.1 정본 명세

- `Sigma_Coding_Convention.md` — **단일 정본.** 모든 판단의 근거는 이 문서다. 검사·수정 전에 통독한다.
  - §1 기본(행 폭·탭 들여쓰기), §2 제외 대상, §3 문법 강제, §4 토큰 4분류, §5 괄호(단일행/다중행·가상 괄호·숨은 중괄호), §6 개행 우선순위, §7 개행 상태, §8 공백, §9 개행 원칙, §10 스타일(네이밍).

### 1.2 워크드 예제 — `app/`

`app/`의 소스는 **그 자체가 규약을 따라 쓰인 모범 예제**다. 규칙을 추상적으로만 읽지 말고, 이 코드에서 규칙이 실제로 어떻게 적용됐는지 대조하며 익힌다.

- `app/lexer.cpp`, `app/lexer.hpp` — **§2 제외 대상의 기준 구현.** 주석(`//`, `/* */` 다중행), 문자열(`"…"` 이스케이프), 문자(`'…'` 숫자 구분자 `1'000` 휴리스틱 포함), 원시 문자열(`R"d(…)d"` 다중행·접두사 `R/LR/uR/UR/u8R`), 전처리기 행(`#…` 통째·`\` 줄연장)을 좌→우 모드 추적으로 가려낸다. "무엇이 코드이고 무엇이 제외 영역인가"의 판단 기준으로 삼는다.
- `app/check.cpp` — **기계검사가 실제로 하는 일.** 어떤 규칙을, 원문 행 위에서 보는지 마스크 위에서 보는지, 위반을 어떤 좌표로 내는지 보여준다.
- `app/main.cpp` — CLI(대상 확장자·재귀·종료코드)와 출력 형식.

## 2. 기계검사(sak)가 커버하는 범위 — 가장 중요

`sak`은 규약 전체가 아니라 **렉서 수준에서 위양성 0으로 확실히 잡히는 규칙만** 검사한다. 단계 1·2·3·3.5·4 의 확장으로 이제 **§3 일부·§5 일부·§8 일부·§9 일부**까지 포괄한다. 1차로 sak을 돌려 이것들을 싸게 걸러낸 뒤, **나머지(와 아래 '커버리지 안쪽의 제외분')는 반드시 직접 검사**해야 한다.

### sak이 잡아주는 규칙 (1차 기계검사로 위임)

|---|---|---|---|
| §1.1 | 행 표시 폭 > 100 (탭=4·전각 CJK=2·그 외=1) | 원문 행 | `1.1` |
| §1.2 | 선두 탭 뒤 공백(들여쓰기에 공백) | 원문 행 | `1.2` |
| §3 | 제어문 중괄호 생략 (`if`/`for`/`while`/`switch`/`do`/`else`; do-while 꼬리 역매칭 포함) | 코드 마스크+인접행 | `3` |
| §3 | 금지 키워드 `typedef`·`goto` | 코드 마스크 | `3` |
| §3 | 키워드 위치 — `const`/`volatile`/`constexpr` 후위·`static`/`inline` 전위 (**기본 타입 키워드 인접분만**) | 토큰 스캐너 | `3` |
| §3 | 단항 병기 — `- -`/`+ +` (**첫 부호가 단항으로 확정되는 자리만**) | 토큰 스캐너 | `3` |

| §5.7 | 다중행 `[[ ]]` 의 닫는 `]]` 가 행 마지막 토큰 | 매처 | `5.7` |
| §8.1 | 들여쓰기 외 탭 / 공백 4칸 이상 연속 | 코드 마스크 | `8.1` |
| §8.2 | 후행 공백·탭 | 코드 마스크 | `8.2` |
| §8.3 | 문맥 불변 기호형 토큰 좌우 공백 — 구분자 (`;` `,`) / BIN_NS (`.` `->` `.*` `->*`) / BIN_S (`=` `==` `!=` `<=` `>=` `<=>` `\|\|` `?` `/` `%` `\|` `^` 와 모든 복합대입) / `++` `--` | 토큰 스캐너 | `8.3` |
| §8.4 | 비기호형 + 여는괄호 사이 공백 / 닫는괄호 + 비기호형 사이 무공백 | 코드 마스크 | `8.4` |
| §8.5 | 단일행 중첩 괄호 안쪽 공백 n (`()` `[]` `{}` 한정) | 코드 마스크 | `8.5` |
| §9.3 | `)` 와 다음 행 단어 사이 개행 금지 | 코드 마스크+인접행 | `9.3` |

### sak 커버리지 **안쪽의 제외분** (그 규칙이라도 아래는 사람이)

sak 가 위 규칙을 보긴 하나, *위양성 0* 원칙상 아래는 일부러 건너뛴다 — **여기는 여전히 사람 몫**이다.

- **§3 제어문 중괄호** — 조건 `(…)` 가 **인접 행(약 4행) 안에 닫히는 경우만**. **3행 이상 걸친 조건**과 **매크로가 본문을 제공하는 경우**는 제외 → 직접 본다. (do-while 꼬리는 정확.)
- **§3 키워드 위치** — **기본 타입 키워드 인접분만** 자동 확정(`const int`·`int static`). **사용자 정의 타입 인접**(`Foo const`/`const Foo`)·다중행 선언은 직접 본다. (`if constexpr` 는 단어쌍이 아니라 자연 제외.)
- **§3 단항 병기** — `- -`/`+ +` 중 **첫 부호가 단항으로 확실한 자리만**(직전이 여는괄호·구분자·양쪽공백 이항연산자). 직전이 피연산자라 단·이항이 갈리는 자리는 직접 본다. (`! !`·`~ ~` 는 붙여도 의미 동일이라 비대상.)
- **§5.4 다중행 괄호** — `< >` (꺾쇠는 비교/템플릿 모호) 제외. 매처에서 잡지 않으니 직접 본다.
- **§5.5 가상괄호** — 다음 앵커는 sak 영역 밖이다:
  - **기본타입 / 사용자 타입 변수선언 `[타입명]『…』;`** — `int x;` 와 `int f();` 가 어휘적으로 동일(vexing parse) 라 sak 가 가를 수 없다.
  - **`:` 가상괄호** — 상속 (`:『 public Base, … 』{`)·생성자 멤버초기화 (`:『 mem(…), … 』{`)·enum 기반 타입 지정 (`:『 unsigned char 』{`). `:` 의 §4 표상 7 역할 가르기가 의미적이라 sak 영역 밖.
- **§8.3 문맥 의존 기호형 토큰** — sak 가 일부러 건드리지 않는 토큰들. 분류가 문맥에 좌우되어 위양성 0 보장 불가.
  - `*` `&` `&&` (역참조/곱셈/주소/데코레이터/참조한정사/우값참조)
  - `+` `-` (단항 부호/이항 산술)
  - `<` `>` (비교/꺾쇠/스페이스십 부분)
  - `:` (§4 표 7 역할)
  - `<<` `>>` (시프트/스트림/템플릿 닫힘 모호)
  - `::` (범위해결 vs 전역)
  - `!` `~` (좌측 공백 룰이 문맥적)
  - `...` (가변인자 / fold)
  - **`operator` 키워드 뒤 첫 기호형은 함수명의 일부라 §8.3 자동 제외**.
- **§8.4** — 꺾쇠 `< >` 가 여는/닫는괄호인 자리(`template<…>`, `static_cast<T>(…)`)는 제외.
- **§8.5** — `< >` 꺾쇠와 `[[ ]]` 와 다중행 괄호는 제외 → §5.4 가 맡는다.
- **§9.3** — `)` + 단어 형태 한 가지만 잡는다. **단어+단어·단어+여는괄호·`}`+단어·공행 분리 자리** 는 §5.5 가상괄호 발현 (다중행 변수선언/using/`:`상속 등) 과 충돌해 sak 무위양성 영역 밖.
- **§9.4** — `§9.2 개행 경쟁 범위로 강제되는 공행` 은 sak 영역 밖. 인접 행이 **전처리 본문 (`\` 연장 행 포함)** 이거나 **주석/문자열 only** 면 들여쓰기 비교에서 제외된다 (§2 제외 대상).

### sak 가 **검출하나 면제 판정이 필요한** 패턴 — 서브에이전트 몫

#### statement-like 매크로 호출 (`BEGIN_CODE_BLOCK(…)` / `END_CODE_BLOCK(…)` 류)

세미콜론 없이 끝나는 매크로 호출이 블록 가드 역할을 하는 패턴 (gtest `TEST(…){…}`, gmock `MOCK_METHOD(…)`, Boost `BOOST_AUTO_TEST_CASE(…)`, Qt 매크로 등 포함). sak 가 §5.4·§9.3·§9.4 위반으로 잡지만 사용자 의도 idiom 일 수 있다.

**서브에이전트 면제 휴리스틱** (다음 모두 만족 시 statement-like 매크로 호출로 가정해 §5.4·§9.3·§9.4 검출을 면제):

1. 식별자가 **ALL_CAPS** (대문자·언더바·숫자만)
2. 식별자 직후 같은 행에 `(...)` 단일행
3. 그 행에 *같은 행 안의 `;` 가 없음* (호출 단독으로 행이 끝)

만족 안 하는 자리 (`ASSERT_EQ(a, b);` 처럼 세미콜론 동반·소문자 함수 호출 등)는 정상 검출을 그대로 신뢰한다.

### sak 이 **못** 잡는 규칙 (반드시 사람이 직접 검사)

- **§3 나머지** — **후행 반환 타입(void 제외) 강제.** 키워드 위치·단항 병기는 sak 이 *기본 타입 인접·단항 확정분* 을 잡으니, 남는 건 **사용자 정의 타입 인접·다중행 선언·단이항 모호분** 뿐이라 이것만 사람이 본다.
- **§4** 토큰 4분류 자체 (sak 의 §8.3 영역 안에서 일부만 분류함).
- **§5.3** 단일행 괄호 경계 투명성 (sak 가 §8.3·§8.5 에서 부분 반영하나 일반 검사는 아님).
- **§6·§7** 개행 우선순위·상태.
- **§9.1** 기호형 토큰의 다중행 자리·전후 공백 — §9.2 종속이라 범주 4.
- **§9.2** 개행 경쟁 범위 — 전 토큰 분류 선행 필요.
- **§10** 네이밍 (비-public 멤버 `_` 접두, static/멤버 대소문자, `I` 금지 + 예외).
- **§11.1** 라행선(囖行線) — 권장 사항.
- **§2 한계** — `#if 0` 등 전처리로 비활성화되는 분기는 sak 가 추적하지 않아 그대로 검사된다. 이 경우 사람이 §2 제외를 판단한다.
- **전각=2 가정** — sak 의 §1.1 폭 계산은 CJK 를 폭 2로 본다(규약 본문엔 멀티바이트 폭 명문 없음). 한글 주석이 많은 파일에서 경계값은 사람이 재확인한다.

## 3. 기계검사 실행 절차

### 3.1 헬퍼 스크립트 (권장)

```sh
.claude/skills/sigma-style/check.sh <file|dir>
```

- `build/sak`이 없으면 자동으로 cmake 구성·빌드 후 실행한다(이후엔 기존 `build/` 재사용).
- 디렉터리를 주면 하위까지 재귀(`-r`) 검사한다.
- **종료코드:** `0` 위반 없음 / `1` 위반 있음 / `2` 사용법·경로 오류. 위반이 있어 1로 끝나는 건 정상 동작이며 스크립트 실패가 아니다.

### 3.2 직접 실행

```sh
cmake -S . -B build && cmake --build build   # 최초 1회 (또는 ./setup.sh)
./build/sak <file>        # 파일 하나
./build/sak -r <dir>      # 디렉터리 재귀
```

### 3.3 출력 파싱

```
<경로>:<행>:<열> [<규칙>] <메시지>
[sak] <N> file(s), <M> violation(s)      # 디렉터리 검사 시 요약 행
```

- 행·열은 1-기준. `<규칙>` 은 `1.1` `1.2` `3` `5.4` `5.5` `5.6` `5.7` `8.1` `8.2` `8.3` `8.4` `8.5` `9.3` `9.4` 중 하나.
- 빌드가 불가능한 환경(컴파일러/cmake 부재)이면 1차 기계검사를 건너뛰고 sak 커버 규칙까지 포함해 **전부 수동 검사**로 전환한다.

## 4. 대상 파일

검사 대상 확장자: `.cpp` `.hpp` `.cu` `.cuh` `.h` (대소문자 무관). 그 외 파일은 건드리지 않는다.
