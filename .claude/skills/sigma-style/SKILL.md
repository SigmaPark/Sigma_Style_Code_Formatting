# Sigma 코드 서식 규약 — 검사·적용 스킬

이 스킬은 두 가지를 제공한다.

1. **규약을 깊이 이해하기 위한 자료의 위치** — 정본 명세와, 규약대로 쓰인 워크드 예제(`app/`).
2. **기계검사 절차** — 빌드된 `sak` 프로그램으로 일부 규칙을 싸고 빠르게 1차 검출하는 방법.

경로는 모두 **이 프로젝트 루트 기준**이다(이 스킬은 `.claude/skills/sigma-style/`에 있으므로 루트는 세 단계 위).

---

## 1. 규약을 이해하는 법

### 1.1 정본 명세

- `Sigma_Coding_Convention.md` — **단일 정본.** 모든 판단의 근거는 이 문서다. 검사·수정 전에 통독한다.
  - §1 기본(행 폭·탭 들여쓰기), §2 제외 대상, §3 문법 강제, §4 토큰 4분류, §5 괄호(단일행/다중행·가상 괄호·숨은 중괄호), §6 개행 우선순위, §7 개행 상태, §8 공백, §9 개행 원칙, §10 스타일(네이밍).

### 1.2 워크드 예제 — `app/`

`app/`의 소스는 **그 자체가 규약을 따라 쓰인 모범 예제**다. 규칙을 추상적으로만 읽지 말고, 이 코드에서 규칙이 실제로 어떻게 적용됐는지 대조하며 익힌다.

- `app/lexer.cpp`, `app/lexer.hpp` — **§2 제외 대상의 기준 구현.** 주석(`//`, `/* */` 다중행), 문자열(`"…"` 이스케이프), 문자(`'…'` 숫자 구분자 `1'000` 휴리스틱 포함), 원시 문자열(`R"d(…)d"` 다중행·접두사 `R/LR/uR/UR/u8R`), 전처리기 행(`#…` 통째·`\` 줄연장)을 좌→우 모드 추적으로 가려낸다. "무엇이 코드이고 무엇이 제외 영역인가"의 판단 기준으로 삼는다.
- `app/check.cpp` — **기계검사가 실제로 하는 일.** 어떤 규칙을, 원문 행 위에서 보는지 마스크 위에서 보는지, 위반을 어떤 좌표로 내는지 보여준다.
- `app/main.cpp` — CLI(대상 확장자·재귀·종료코드)와 출력 형식.

## 2. 기계검사(sak)가 커버하는 범위 — 가장 중요

`sak`은 규약 전체가 아니라 **렉서 수준에서 위양성 0으로 확실히 잡히는 규칙만** 검사한다. 커버리지가 넓어져 이제 **§8.1·§8.5·§3 제어문 중괄호까지** 포함한다. 1차로 sak을 돌려 이것들을 싸게 걸러낸 뒤, **나머지(와 아래 '커버리지 안쪽의 제외분')는 반드시 직접 검사**해야 한다.

### sak이 잡아주는 규칙 (1차 기계검사로 위임)

| 규약 | 검출 내용 | 대상 | 출력 `[규칙]` |
|---|---|---|---|
| §1.1 | 행 표시 폭 > 100 (탭=4·전각 CJK=2·그 외=1) | 원문 행 | `1.1` |
| §1.2 | 선두 탭 뒤 공백(들여쓰기에 공백) | 원문 행 | `1.2` |
| §8.1 | 들여쓰기 외 탭 / 공백 4칸 이상 연속 | 코드 마스크 | `8.1` |
| §8.2 | 후행 공백·탭 | 코드 마스크 | `8.2` |
| §8.5 | 단일행 중첩 괄호 안쪽 공백 n (`()` `[]` `{}` 한정) | 코드 마스크 | `8.5` |
| §3 | 제어문 중괄호 생략(`if`/`for`/`while`/`switch`/`do`/`else`) | 코드 마스크+인접행 | `3` |
| §3 | 금지 키워드 `typedef`·`goto` | 코드 마스크 | `3` |

> sak 메시지: `tab outside indentation`·`4 or more consecutive spaces`(§8.1), `inner space must be N`(§8.5), `<키워드> needs braces`(§3 제어문), `banned keyword: …`(§3 금지어).

### sak 커버리지 **안쪽의 제외분** (그 규칙이라도 아래는 사람이)

sak이 §8.5·§3을 보긴 하나, *위양성 0* 원칙상 아래는 일부러 건너뛴다 — **여기는 여전히 사람 몫**이다.

- **§8.5** — sak은 `()` `[]` `{}` **단일행만**. **`< >`**(템플릿/비교가 렉서 수준 미결정)·**`[[ ]]`** 어트리뷰트·**다중행 괄호**(§5.4 정렬)는 제외 → 직접 본다.
- **§3 제어문 중괄호** — 조건 `(…)`가 **인접 행(약 4행) 안에 닫히는 경우만**. **3행 이상 걸친 조건**과 **매크로가 본문을 제공하는 경우**는 제외 → 직접 본다. (do-while 꼬리는 직전 `}`를 여는 `{`까지 역매칭해 `do`인지 확인하므로 정확. 빈본문 `for(…);`·꼬리 아닌 `while(…);`·생략은 위반으로 잡힌다.)

### sak이 **못** 잡는 규칙 (반드시 사람이 직접 검사)

- **§3 나머지** — `const`/`volatile`/`constexpr` 후위·`static`/`inline` 전위, 후행 반환 타입(void 제외) 강제, 단항 연산자 괄호 병기.
- **§4** 토큰 4분류, **§5** 괄호 전반(§5.3 경계 투명성, §5.4 다중행 정렬, §5.5 가상 괄호, §5.6 숨은 중괄호), **§6·§7** 개행 우선순위·상태, **§8.3·§8.4** 공백 규칙, **§9** 개행 원칙(§9.2 경쟁 범위·§9.4 공행), **§10** 네이밍.
- **§2 한계** — `#if 0` 등 전처리로 비활성화되는 분기는 sak이 추적하지 않아 그대로 검사된다. 이 경우 사람이 §2 제외를 판단한다.
- **전각=2 가정** — sak의 §1.1 폭 계산은 CJK를 폭 2로 본다(규약 본문엔 멀티바이트 폭 명문 없음). 한글 주석이 많은 파일에서 경계값은 사람이 재확인한다.

## 3. 기계검사 실행 절차

### 3.1 헬퍼 스크립트 (권장)

```sh
.claude/skills/sigma-style/check.sh <file|dir>
```

- `build/sak`이 없으면 자동으로 cmake 구성·빌드 후 실행한다(이후엔 기존 `build/` 재사용).
- 디렉터리를 주면 하위까지 재귀(`-r`) 검사한다.
- **종료코드:** `0` 위반 없음 / `1` 위반 있음 / `2` 사용법·경로 오류. 위반이 있어 1로 끝나는 건 정상 동작이며 스크립트 실패가 아니다.

### 3.2 직접 실행

```sh
cmake -S . -B build && cmake --build build   # 최초 1회 (또는 ./setup.sh)
./build/sak <file>        # 파일 하나
./build/sak -r <dir>      # 디렉터리 재귀
```

### 3.3 출력 파싱

```
<경로>:<행>:<열> [<규칙>] <메시지>
[sak] <N> file(s), <M> violation(s)      # 디렉터리 검사 시 요약 행
```

- 행·열은 1-기준. `<규칙>`은 `1.1` `1.2` `8.1` `8.2` `8.5` `3` 중 하나.
- 빌드가 불가능한 환경(컴파일러/cmake 부재)이면 1차 기계검사를 건너뛰고 sak 커버 규칙까지 포함해 **전부 수동 검사**로 전환한다.
